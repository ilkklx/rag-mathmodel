# 研究笔记（这套东西是怎么来的）

## 一、语料是怎么选出来的

1. 扫描 F/E 盘 **21,433 个文件**、5,346 篇 PDF；
2. PDF 抽样 400 个做可解析性归因：正常文本 69.0%、**加密 27.5%**、图片型 3.5%；
3. 加密件再抽 85 个试空密码，**83 个可解** → 一行 `reader.decrypt("")` 把可用语料从 69% 抬到约 96%；
4. **重大发现**：`zhanwen/MathModel` 的 687 篇"国赛论文"里 **533 篇其实是研赛（华为杯）**（首页原文实证）；
5. 重分类后：**本科生国赛 902 篇 / 1,345 万字 / 766 篇解析可用**，研赛 705 篇剔除。

## 二、索引是怎么建的

- 按**官方章节结构**切块（摘要 / 问题重述 / 问题分析 / 模型假设 / 符号说明 / 模型建立与求解 / 模型检验 / 模型评价 / 参考文献 / 附录），**不按字数硬切**；
- 全库 17,231 块，国赛库 16,373 块；本包索引 **8,951 chunk**（373 篇材料）；
- 向量：`BAAI/bge-small-zh-v1.5`（fastembed / ONNX，不装 torch）；
- 词法：SQLite FTS5 `tokenize='trigram'`。

## 三、算法普查（决定"该学什么"）

| 全体 Top | 命中块数 |

| 只看 A 题 | 命中块数 |
|-----------|----------|
| 参数辨识/拟合 | 202 |

## 四、评测是怎么做的

- 冻结 **50 题 GT**（建模方法/算法/公式与数学关系/相似赛题/综合，五类各 10）；
- **三种口径分开陈述**：legacy 文件级命中、内容级语义命中（DirectHit/MRR）、Phase 6 槽位与去重双分母；
- 评测集本身出过错，修正过程留痕（`gt_changed` / `old_gt`）。

## 五、做过哪些实验，结论是什么

| 阶段 | 做了什么 | 结论 |
|------|----------|------|
| Phase 4 | 文档去重（固定文档上限） | **不启用**（会伤召回） |
| Phase 5 | 查询改写 A/B | **采用 Scheme-B**；Scheme-A 零额外收益 |
| Phase 5.1 | 内容级语义评测 | 自动指标改善 ≠ 内容改善，必须分开报 |
| Phase 5.2 | Q-1 修复（2 字词） | 采用；补首字会造伪词 |
| Phase 6 | 聚合检索（三条件对照） | **负结果**：不增加唯一 DIRECT 赛题，默认关闭 |
| Phase 6 诊断 | 5 题失败归因（四轮修订） | 撤销过 3 条早期结论；最终只保留可复算的部分 |
| 分层记录 | 已知材料停在检索哪一层 | 用受限补测逐层落盘，含强制一致性校验 |

## 六、方法论上的三条硬规矩（本包沿用）

1. **汇总数字必须脚本产出**（曾出现手写数字与 JSON 不符）；
2. **负结果照实交付；撤销要明说撤回**；
3. **交付包必须经外部独立复验**才能封存，自查只能算自检。
